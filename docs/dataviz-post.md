# Making a data-visualization post for adamsohn.com

How the five posts on this site are built, so the sixth does not re-derive it.
Point an agent at this file before it writes a line of the new post.

Every rule below is drawn from a post that already shipped. Where a rule exists
because something broke, the breakage is named, because the reason is what makes
the rule survivable when you are tempted to skip it.

---

## 1. Where the post lives

**Not in this repo.** `~/Projects/blog` is a deployment manifest: it holds the
built `dist/` of each post plus a plain-HTML homepage, and whatever is on `main`
is what is on the site. `git log` is the deploy history and `git revert` plus a
push is the rollback.

The post gets its own repo, or its own subdirectory of the repo that produced
the data. Both patterns are in use:

| URL | Source | Shape |
|---|---|---|
| `/reasoning-grid/` | `~/Projects/carrychain/blog/` | post lives beside the `probe/` scripts that generated its numbers |
| `/clap/` | `~/Projects/clap/post/` | post beside `toy/`, the Python that trains the model and exports the data |
| `/grpo/` | `~/Projects/grpo/post/` | same shape as clap |
| `/separate/` | `~/Projects/separate/` | the repo root *is* the app; data prep in `scripts/` |
| `/reliably-incorrect/` | `~/Projects/agent-capability-threshold/web/` | the oldest, and the source of several components the others copy |

Note that the repo name and the URL do not have to match. `/reasoning-grid/` is
built from a repo called `carrychain`. If you cannot find a post's source, grep
the source repos for the deployed `<title>` rather than guessing from the path.

Put the post beside its data when the data is generated by code you own. The
separation that matters is raw versus derived, not Python versus TypeScript, and
keeping them in one repo means one commit can change a number and the chart that
shows it.

## 2. Shipping it

```sh
cd ~/Projects/blog
./scripts/sync-app.sh ~/Projects/<source-dir> <subpath>   # npm ci, npm run build, copy dist/
$EDITOR index.html                                        # add a <dt>/<dd> under the right <h2>
./scripts/gen-sitemap.sh                                  # rescans; no list to maintain
git add -A && git commit && git push                      # CI does s3 sync + CloudFront invalidation
```

`sync-app.sh` does `rm -rf` on the destination before copying, so anything you
hand-edited inside `blog/<subpath>/` is gone on the next sync. Fix it in the
source repo.

The AWS side (S3, CloudFront, OAC, ACM, Route53, the `www` redirect function)
is in [`.claude/CLAUDE.md`](../.claude/CLAUDE.md). The bucket name, distribution
id and role arn live in [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml)
and are not repeated here, so there is one place to change them.

## 3. Four things that break silently

These do not fail the build. They ship, and the page looks fine to you.

**`base: './'` in `vite.config.ts`.** `sync-app.sh` copies one build to an
arbitrary subpath, so every asset URL has to be relative. Absolute URLs give you
a blank page at `/newpost/` and a working one at `localhost`. Every post on this
site sets it; copy the line and its comment.

**Open Graph tags are the exception to that rule.** Facebook, iMessage and Slack
resolve `og:image` against nothing, so those four tags need the full
`https://adamsohn.com/<subpath>/...` URL. They are the only absolute URLs on the
page, which means they are also the only thing that breaks if the deploy path
ever moves, and they break invisibly: the page still works, the preview just goes
blank. `reasoning-grid/index.html` carries a comment saying exactly this; keep it.

**`noindex`, not `Disallow`.** `gen-sitemap.sh` includes every `*/index.html`
that does not carry a `noindex` robots meta tag, so the tag in the page is the
only switch and there is no exclude list to keep in sync. Do not reach for
`robots.txt` instead: a `Disallow` stops the fetch, a crawler that never fetches
never reads the `noindex`, and the bare URL can still get indexed from an
external link. Leaving the page crawlable is what makes the `noindex` work.

**The deploy syncs the repo root to S3.** `deploy.yml` excludes `.git/`,
`.github/`, `scripts/`, `.claude/`, `CLAUDE.md`, `.gitignore`, `.DS_Store` and
`docs/`. Anything else you drop at the root is public at `adamsohn.com/<name>`.
Adding a new top-level file means adding an exclude, or accepting that it ships.

## 4. The stack

Svelte 5 with runes (`$state`, `$derived`, `$props`, `$effect`), Vite,
TypeScript. No framework beyond that, no SvelteKit, no component library.

**Charts are hand-written inline SVG.** No Recharts, Chart.js, Plotly or
Observable Plot anywhere on this site. d3 is present but only as `d3-scale` for
axis math, plus `d3-brush` and `d3-selection` in the one component that brushes.
No `d3.axis`, no selections driving rendering. Paths, ticks and labels are
written out.

This is worth keeping. Inline SVG in a component inherits CSS custom properties,
so the theme is one stylesheet; it stays crisp at any zoom; it is readable in
DevTools; and it is accessible without extra work. The threshold where it stops
being right is **roughly a few thousand elements**. Dense scatter plots and
per-pixel work go to Canvas 2D, and to WebGL only when the geometry genuinely
needs a GPU. The Rubik's cube in `/grpo/` is 3D and still SVG: an isometric
projection to polygons, painter's algorithm for depth, `cross2D` on the projected
winding for back-face culling. Under a few thousand elements, reach for SVG.

`katex` for math, `@playwright/test` for the snapshot and verification scripts.

## 5. House style — do not re-pick this

`src/app.css` carries the design tokens and is copied between posts. A post that
invents its own palette reads as a different site.

| | |
|---|---|
| paper | `#fdfcf9`, panels `#f7f5f0`, deeper panel `#f0ede5` |
| rules | `#e8e4dc`, strong `#d8d2c4` |
| ink | `#1a1a1a`, dim `#5a5a5a`, faint `#9a9a9a`, faded `#c8c4bb` |
| accent | navy `#1f3a5f`, hover `#2d4a73` |
| body | `"Source Serif Pro", "Charter", "Iowan Old Style", Georgia, serif` |
| sans | `"Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |
| mono | `"JetBrains Mono", "SF Mono", ui-monospace, monospace`, `tabular-nums` on figures |
| reading measure | **640px** |
| figure width | **880px** |
| page shell | 1100px, only on chart-heavy posts |

Type scale, leading, weights and the 4/8/16/24/40/64/96px spacing steps come with
the file. Take them whole.

**The font stacks must match character for character.** Four of the five posts
load no webfont at all, so the stack is what resolves to a local family. Leading
with `"Source Serif 4"` instead of `"Source Serif Pro"` makes two posts render
differently on the same machine. `/clap/` is the outlier: it leads with Source
Serif 4 and pulls it from Google Fonts. Match the other four.

**Two token naming families exist. Pick one and know which.**

| Concept | grpo, separate | clap, reasoning-grid |
|---|---|---|
| reading measure | `--measure` | `--maxw` |
| figure width | `--figure-width` | `--maxw-fig` |
| panel | `--surface`, `--surface-muted` | `--panel`, `--panel-2` |
| rule | `--border`, `--border-strong` | `--line`, `--line-strong` |
| secondary ink | `--ink-muted`, `--ink-subtle` | `--ink-dim`, `--ink-faint` |

Same hex values, different names. Copying a component across the divide gives you
an element styled with undefined variables, which renders as unstyled rather than
as an error. `reasoning-grid` handles this by aliasing (`--measure: var(--maxw)`)
so components copied either direction resolve. Do that rather than editing the
copied file, and a later diff against the source still works.

**What is yours to choose is the semantic mapping**, at the bottom of `app.css`.
Each post assigns the shared hues to its own quantities and then holds that
assignment for the whole page. `reasoning-grid` does it like this:

| token | means |
|---|---|
| `--ramp-lo` → `--ramp-hi` | reliability: one warm hue, pale to deep |
| `--model-a` | Qwen3-4B, cool |
| `--model-b` | Phi-4-reasoning, warm |
| `--fit` | fitted boundary and UI focus, navy, nothing else |
| `--absent` | no data, faint grey, **never** a low score |

That last row is the one people get wrong. A cell with no measurement and a cell
measured at zero must not look alike.

## 6. Page skeleton

```text
post/
├── index.html              <head>, OG tags, no-JS rules
├── vite.config.ts          base: './'
├── scripts/                data prep, snapshots, build-time checks
├── public/data/            reduced JSON, fetched at runtime
└── src/
    ├── main.ts
    ├── app.css             tokens + this post's semantic mapping
    ├── App.svelte          composes <Section> blocks, one per beat of the argument
    └── lib/
        ├── components/     Layout, Section, Prose, Figure
        ├── data/           typed loaders for the JSON
        └── viz/            one component per figure
```

`App.svelte` is the outline of the argument and nothing else. Read
`reasoning-grid`'s to see the shape: each `<Section>` is one beat, figures are
imported at the top, and the state that couples prose to a figure is owned in
`App.svelte` rather than inside the figure. **The figure reports, the prose
renders.** A figure that reaches up into page copy cannot be reused or removed.

The component contract, from `Section.svelte`:

- `width="measure"` (default, 640px), `"figure"` (880px), or `"page"` (1100px).
- **The header always stays at the measure**, so a wide figure never drags its
  own title out to the edge.
- Prose inside a wide section still renders at the measure and stays in the same
  column as the header. Getting this wrong indents every heading relative to the
  body text under it, and it is only visible at wide viewports.
- `.body > :global(*) { min-width: 0 }` is load-bearing. Without it an 880px
  chart refuses to compress and pushes the whole page wide on a phone.

Charts sit **inside** a narrow reading column. A chart authored standalone at
940–1120px needs refitting, not just recolouring, and refitting is the expensive
part. Author at 640 or 880 from the start.

Pick a dev port nothing else uses and set `strictPort: true`. `grpo` and
`separate` both sit on 5174, and `reasoning-grid` set `strictPort` after Vite
silently fell through to another port and a measuring script pointed at whatever
project happened to hold it.

## 7. The data pipeline

The same four steps everywhere:

```text
1. code that produces numbers   ->  raw output, immutable, committed
2. a committed reduce script    ->  small JSON in post/public/data/
3. a typed loader in lib/data/  ->  fetched at runtime
4. a Svelte component           ->  inline SVG
```

Raw is whatever the run produced, kept exactly as produced, never edited to fix
a downstream parser. Everything after it is derived and regenerable. The browser
never sees a raw record, and the reduction is a committed script rather than a
notebook, so the chart can be rebuilt from scratch at any time.

Where this pays: `reasoning-grid` re-derives scores from raw text on every
reduction instead of reading back stored scores, because its answer parser
shipped broken four times. A stored score goes stale silently. A re-derived one
does not.

No Python plotting anywhere on this site. No matplotlib, seaborn, plotly, altair
or bokeh. Charts are built in the browser from JSON, never rendered server-side.

**Ship precomputed unless live computation is the point.** `/separate/` runs its
audio model offline in `scripts/prepare_clips.py` and serves only the results, so
the walkthrough works on any device. `/clap/` computes its forward pass live in
the browser because "every value is real" is the claim the post is making, and it
is verified bit-exact against the PyTorch reference. Decide which post you are
writing before adding a runtime model.

## 8. Choosing the chart

Form first, then colour.

**One hue for sequential data.** Probability, rate, magnitude: one hue, pale to
deep. A rainbow invents boundaries the numbers do not have.

**Two hues with a neutral midpoint for diverging data.** A difference map, model
A minus model B, a grid minus its own transpose.

**Categorical hues are assigned in fixed order and never cycled.** From the
validated palette below, which passed lightness-band, chroma-floor,
colour-blind-separation and contrast checks in both themes:

```text
light:  #2a78d6  #eb6834  #1baf7a  #eda100  #e87ba4  #008300  #4a3aa7  #e34948
dark:   #3987e5  #d95926  #199e70  #c98500  #d55181  #008300  #9085e9  #e66767
```

**A contrast warning is not dismissable.** It obliges a visible label or a table
view.

**Encode uncertainty or the reader will assume there is none.** Cells that differ
in sample size need opacity or a hatch. A rate quoted bare invites a reader to
read noise as signal, so state the interval alongside it. Near the extremes the
interval is wide enough to reverse the reading.

**Distinguish invalid from zero.** A cell that failed a validity rule is greyed,
not dark.

Before building anything, read
[`carrychain/.agents/reference/dataviz/README.md`](../../carrychain/.agents/reference/dataviz/README.md).
It surveys what already exists across these projects so a technique gets reused
rather than reinvented, and names the specific components worth reading first:
`Consistency.svelte` for a running rate with a Wilson band, `CapabilityCurves.svelte`
for log-x curves with a reference line, `ThinkingOps.svelte` for annotated trace
segments.

## 9. What reasoning-grid learned the hard way

`/reasoning-grid/` is the most developed post and the right one to copy from. Its
extra machinery exists because of specific failures.

**Prerender the prose.** A static SPA on S3 ships an empty `<div id="app">`, with
every word of the essay inside a couple hundred KB of gzipped JavaScript.
Crawlers that do not run JS, archive.org, reader-mode tools and `curl` get
nothing, and a reader on a slow connection watches a blank screen. The fix is a
second SSR build plus `scripts/prerender.mjs`:

```text
vite build && vite build --ssr src/entry-server.ts --outDir dist-ssr && node scripts/prerender.mjs
```

The prerender asserts on a **canary sentence** from near the start of the essay
*and* one from near the end, plus a body-length floor. One canary only proves the
prerender emitted something. The first version's canary sat at character 881 of
13,005, so a bug truncating the other 93% would have passed.

**Figures are not prerendered, so hold their boxes open.** Canvas, rAF and
`matchMedia` cannot run on the server, so figures mount on the client about a
tenth of a second after the prose paints. Without a reserved box the reader gets
the essay and then watches nine figures shove it down the page.

The heights are **measured, not guessed**: `scripts/measure-figures.mjs` sweeps
the real page across 32 widths and writes `figure-heights.css`, with `--check` to
fail CI when a figure changes and the file goes stale. Per figure, not per tier,
and not by aspect ratio: the opener is 510px tall on a phone and 517px on a
desktop three times as wide, while the trace figure is 891px on a phone and 542px
on a tablet, getting *shorter* as the screen widens. One `aspect-ratio` rule
would be wrong at every width.

**Give the no-JS reader a picture and a sentence.** `Figure.svelte` renders a
still image plus the alt text inside `<noscript>`. Markup inside `<noscript>` is
not parsed when scripting is on, so the image is never requested and a megabyte
of animation costs the normal reader nothing.

**Flip `mounted` in `onMount`, not `typeof window !== 'undefined'`.** The latter
is already true on the first client render, which is the hydration pass, so the
client's output disagrees with the server's.

**Render controls unconditionally.** Gating them on mount makes them appear at
hydration, growing the page under a reader who already started reading, and it
keeps their anchors out of the prerendered HTML where a fragment has to be for
the browser to resolve it. A `<noscript>` rule in `index.html` hides them from the
one reader who cannot use them.

**Every check must be able to fail.** `verify-deploy.mjs` carries this lesson in
a comment. Its first version read each figure box at `domcontentloaded`, called
that "reserved", read it again after load, called that "actual", and compared.
Module scripts are deferred and run before `DOMContentLoaded`, so both readings
were the same post-hydration DOM, every delta was exactly 0, and deleting the
entire stylesheet the check existed to guard still printed "ok". Two reviews
found it, and only by trying to make it fail. Before trusting a new check, break
the thing it guards and confirm it goes red.

Same principle on counts: assert `FIGURE_COUNT === 9`, updated deliberately, not
`> 0`. The loose version passed happily when a figure was deleted along with its
section.

**Generate the OG card.** `npm run og` builds `og.png` from a committed script,
at 2x a 1200x630 layout. The `og:image:width`/`height` tags are the card's real
pixels, so they change when the script does.

## 10. The visual iteration loop

This is a portfolio site. After any UI change, run the snapshot loop and read the
screenshots before claiming done.

```sh
npm run dev
npm run snapshot -- --label=iter-NN-topic [--action=...]
```

It loads the page at desktop (1440x900), tablet and mobile, captures full-page
and above-the-fold PNGs, and records console errors, page errors, network
failures and DOM overflow into `.snapshots/<label>/`. Read the images. Compare
against the previous iteration.

A section is not done until tri-viewport snapshots pass:

- no horizontal overflow (`document.documentElement.scrollWidth <= window.innerWidth`)
- zero console, page and network errors
- tap targets at least 44px
- no hover-only interaction
- `prefers-reduced-motion` honoured

`reasoning-grid/scripts/viewports.mjs` is a 15-line version that just prints
document width and every SVG width across five device sizes, flagging overflow.
Worth copying for a quick check between full snapshots.

## 11. Writing

Follow the anti-slop rules
([`carrychain/.agents/reference/anti-slop.md`](../../carrychain/.agents/reference/anti-slop.md),
the fullest copy, 11 rules). The short version: start with the point, plainest
accurate word, at most one em-dash per paragraph, no filler phrases, no "not just
X, it's Y", concrete numbers and named references, take a position, prose over
bullets, no redundant summary, vary sentence rhythm, and no participial tails
("The system analyzes the data, revealing key insights") — that last one is a top
tell of machine prose.

Voice is **first person singular**. `grpo` has a commit that converts the whole
post from `we/our/us` to `I/my/me`; match it.

**State results plainly, including negative ones.** A run that failed, a cell
skipped, a prediction that missed are all reportable outcomes, and burying them
costs more credibility than the failure did. `reasoning-grid`'s README opens by
retracting the hypothesis the project was built to test, and its `blog/README.md`
retracts a specific set of numbers an earlier draft promised. That is the
standard.

Before publishing, run the `prose-review` skill
([`carrychain/.agents/skills/prose-review/SKILL.md`](../../carrychain/.agents/skills/prose-review/SKILL.md)).
It reads the text phrase by phrase for misreadings and checks each candidate
against a reader who has not seen the reasoning.

**Link the companion posts.** These posts cross-reference each other in the
prose, in normal sentences rather than a "related links" block. `/clap/`,
`/separate/` and `car-diagnosis` are one body of work; `/reasoning-grid/`,
`/reliably-incorrect/` and `/lambda-variance/` are another.

## 13. Before you push

- [ ] `npm run check` clean (`svelte-check`)
- [ ] `base: './'` set; grep the built `dist/index.html` for absolute asset paths
- [ ] OG tags carry the full `https://adamsohn.com/<subpath>/` URL, and `og.png` exists
- [ ] `npm run build && npm run preview`, then verify against the preview URL
- [ ] figure heights re-measured if any figure's layout changed (`--check` passes)
- [ ] tri-viewport snapshots read, not just captured
- [ ] prose-review run
- [ ] `sync-app.sh`, `<dt>/<dd>` added to `index.html`, `gen-sitemap.sh` re-run
- [ ] after CI: verify against the live URL, and paste the link somewhere that
      renders an OG card to confirm the preview is not blank
